# OCR 模型与评估结果

## 模型选择

| 用途 | 建议模型 | 验证范围 |
|---|---|---|
| 简中通用 OCR | 官方 PP-OCRv6 small，不微调 | 国服实图支持升级；本批对照未体现微调的额外收益 |
| 繁中、英文、日文通用 OCR | 同一官方 PP-OCRv6 small 与完整原字典 | 可用作初始模型，仍需各客户端实图验证 |
| 韩文通用 OCR | 官方 Korean PP-OCRv5 mobile 与原字典 | 导出一致性通过，韩服实图质量待验证 |
| CharOCR | PP-OCRv6 small ASCII 专用微调 | 开发回归通过；训练用过的关卡图不计独立准确率 |

v6 保留官方字典顺序，Char 将输出层映射到 ASCII 子集后训练。韩文直接导出官方模型时应使用原字典；训练配置中的扩展字典另含 `★`、`《`、`》`，增加的输出类别需要训练，不能直接配给原权重。

## 通用 OCR：同条件三方对照

2026-10-03 在同一 MAA v6.18.0 Linux 发布核心上，固定检测器、线程、图片和裁剪，对照原识别模型、官方 v6 预训练及国服微调模型。原文按大小写、空格和标点完全匹配；完整 Logo 则在检测后匹配预先规定的文字目标。业务测试固定官方 Char，以隔离通用模型的影响。

| 检查项 | 原识别模型 | 官方 v6 预训练 | 国服微调模型 |
|---|---:|---:|---:|
| 单行完整原文 | 62/82 | 82/82 | 81/82 |
| 其中单行特殊字体 | 4/12 | 12/12 | 12/12 |
| 完整 Logo 文字目标 | 2/8 | 4/8 | 4/8 |
| 业务正例 | 9/9 | 9/9 | 9/9 |
| 已知失败保持失败 | 1/1 | 1/1 | 1/1 |

微调模型唯一新增差异为 `今日答案!` → `今日答案！`，是全／半角叹号差别；没有新增正确项，也不能据此推断文字内容或艺术字能力退步。两种 v6 共同失败的 Logo 还涉及检测分割、裁剪和空格，不能只靠识别模型解决。因此通用模型先采用官方预训练权重，有实图证据后再决定是否微调。

82 条文字来自 10 份原图；业务案例来自 8 张另行采集、未参与训练及选版的截图，两部分有复用，共 16 份去重原图。公开 issue 偏向故障场景，同图多条文字也有关联；标签由 GPT 在推理前识图标注，未经过第二名人类独立复核。这些结果不能外推为全游戏准确率。

## CharOCR：训练规模与结果

Char 基础集为 20,000 张训练图、2,000 张开发图，另保留 120 张不参与更新的保护样本。基础训练 batch 16、学习率 `5e-6`、500 步；随后加入 4 张已核对真实关卡图生成的 448 个训练变体，以学习率 `2e-6` 训练 300 步，选择最早达到相同结果的第 100 步。真实关卡来源固定为 `MaaTestSet@dfb2238c`，这些图及变体仅用于训练和开发回归。

| 同一开发评判集 | 原 MAA v6.18.0 模型 | 入选 Char 模型 |
|---|---:|---:|
| 原始识别 | 227/239 | 238/239 |
| 任务规则结果 | 79/79 | 79/79 |

入选模型的 120 张保护样本全部正确，导出数值一致性检查通过（46 项）。`0-1`、`OF-F4`、`10-3`、`10-16` 和真实费用 `0` 回归通过。上述开发成绩用于选版，不能代替独立实图验收。

数据生成配方也支持五条通用路线，每条为 10,000 张训练图、2,000 张开发图；加上 Char 基础集共 82,000 张，加入 Char 变体后共 82,448 张。该规模是已运行的预算配置，并非对所有版本都最优；新场景应先补充覆盖，再做等训练预算的扩量对照。

## 结果文件与复查方法

- [evaluation.json](evaluation.json)：模型／运行库身份、最终计数、公开原图来源与 Logo 结果，以及入选 Char 的训练参数和哈希。
- [evaluation-cases.csv](evaluation-cases.csv)：67 条可公开的单行样本，含原图 ID、XYXY 坐标、标签、裁剪哈希和三方输出；正确数分别为 **47/67、67/67、66/67**。

复查公开子集时，按 JSON 中的来源取得原始字节并核对 SHA-256；ZIP 来源还需核对归档哈希和条目路径。按 CSV 坐标裁剪、转 RGB 并保存 PNG（原裁剪使用 Pillow 12.3.0），可核对裁剪哈希。按[训练与导出入口](../pipeline/README.md)准备模型，并将绝对裁剪路径写入 JSONL，例如 `{"id":"001","image":"/path/to/001.png","mode":"rec"}`。模型目录应含 `rec/inference.onnx`、`rec/keys.txt` 及同一发布版的 `det/`，然后运行：

```bash
export LD_LIBRARY_PATH="$OCR_WORK/toolchains/native/lib:$OCR_WORK/releases/v6.20.1${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
"$OCR_WORK/build/maa_ocr_probe" "$OCR_WORK/releases/v6.20.1" \
  /path/to/model-pack /path/to/cases.jsonl "$OCR_WORK/check/word.json" \
  0 0 0 Official word
```

此例对应当前 v6.20.1 检查；复现三方对照需要改用其记录的 v6.18.0 源码、发布包和同版本构建的探针。三个 `0` 关闭预热及计时循环，不关闭识别。将每条 `predictions[].results[].text` 按 CSV 的原文严格计分，不提前删除空格或统一标点。

私人截图、模型二进制、完整训练日志及开发期报告不随仓库提供。67 条公开结果可逐项复查；其余 15 条及完整私人业务输入不能由这里的公开文件单独重建。训练权重完成于 v6.18.0 阶段，后续代码整理和 v6.20.1 回放没有重训，新的训练应重新冻结实际源码与输入。
